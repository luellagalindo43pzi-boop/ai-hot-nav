# 智能体回复与日报导出设计

## 设计参考

- [`mvanhorn/last30days-skill`](https://github.com/mvanhorn/last30days-skill)：参考其将研究请求拆成时间范围、来源搜索、证据综合的工作流，以及 BYO-key、安全处理和明确来源/不确定性的方式。本站实现独立编写，不复制其代码。
- [`cathrynlavery/diagram-design`](https://github.com/cathrynlavery/diagram-design)：参考其“先明确交付物类型，再按目标格式导出”的交互思路。本站聚焦研究日报/简报的可移植文档格式，不复用其绘图实现。

## 模式

- 自动判断：根据用户请求识别推荐、研究、日报或比较。
- 站点推荐：基于目录词项匹配，说明适用场景及热度/质量参考。
- 研究简报：区分事实、推断、建议与未知项。
- 主题日报 / 周报：用户可设置 1、3、7、30 天检索范围；要求模型按 schema 返回 JSON，再校验输出中引用的 URL 是否在本轮上下文中。无匹配来源的链接会移除并加入局限说明。
- 方案对比：用表格比较，未知信息标为未核实。

## 导出

当用户生成主题日报或周报后，浏览器使用最后一份结构化报告导出：Markdown、HTML、JSON、CSV、纯文本。CSV 带 UTF-8 BOM，便于常见表格应用识别中文。文件只在浏览器生成，不会上传。HTML 文档转义模型文字，链接只由校验后的 URL 创建。

## 可验证边界

浏览器日报上下文来自本站目录、当前配置的搜索工具、GitHub Search API 与已加载的最新站内日报。没有搜索结果时，系统提示应避免声称完成实时网络研究。搜索摘要不是来源原文的替代品；正式发布前仍应检查链接和内容。
